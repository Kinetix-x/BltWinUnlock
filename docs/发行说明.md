# Btwu —— 带上键盘走开就锁屏，回来按一下回车就进去

> 一段可以直接贴到发布页的介绍。写的是当前版本的实际行为，优缺点都照实说。

## 为什么写它

我用的是一把蓝牙键盘。离开工位时电脑锁屏（Win+L 或超时），回来还得输一遍密码——可键盘就在手边，连着，能打字。

也就是说：**「我人在」这件事，机器早就知道了，只是没人告诉锁屏界面。**

Windows 自带的两条路都走不通：

- **动态锁**（Dynamic Lock）配对手机，它只会**替你锁**，永远不会替你解锁；
- **Windows Hello** 要指纹或红外摄像头，台式机上基本没有。

而一把蓝牙**键盘**其实是比手机更干净的在场证据：它是 HID 设备，链路只在一定范围内维持，而且你此刻正在用它打字。所以我把判据放在它身上——**键盘连着，就当你人在**。

## 它是怎么做到的

一句话：**一个凭据提供程序、一份保管的口令、一个盯着蓝牙的小进程。**

1. 常驻小进程看着键盘的蓝牙连接状态，往 `presence.dat` 写一行：在场 / 不在场。
2. 自研的 Windows **凭据提供程序**（锁屏上那块密码磁贴就是它的同类）读那一行：在场就把保管的口令按锁屏的要求打包好交给 Windows——**你按一下回车就进来了**；不在场就**一个凭据都不提供**，锁屏和平时一模一样。
3. 口令用 DPAPI 加密存在本机（`cred.bin`，只有 SYSTEM 和管理员能读）。
4. 判据取自 Windows 自己的 PnP 设备树：**HID 身份 + 蓝牙地址精确匹配**——不是设备名字，也不是信号强度。

默认是**回车模式**：锁屏界面完整保留 Windows 原样，只是多了一个「按回车即可」的默认凭据。想要「锁屏直接回桌面」，命令行里有开关：`btwu autosubmit on`。

**它不负责锁屏。** 什么时候锁由 Windows 自己决定（合盖、超时、Win+L）——那件事 Windows 做得很好，而这个工具存在的理由只是「不用输密码」。

## 优点

- **任意蓝牙键盘（或鼠标）都行**，不需要额外硬件、不需要指纹或摄像头。
- **判据是设备身份，不是信号强弱**：按蓝牙地址精确匹配，手机、耳机、手环、音箱不会因为在隔壁房间连着就冒充你。
- **不是「无密码开机」**：冷启动和注销后仍然要输一次密码，UAC 提权框永远不解锁——两处都是刻意设计。
- **fail closed**：凭据提供程序在任何异常路径上都返回 0 个凭据。最坏的情况是「不解锁」，绝不会把锁屏界面弄坏（登录界面失去 UI 那种事故，这个项目专门修过一轮）。
- **绿色版**：一个文件夹、双击即用，装的时候一次 UAC，之后日常零管理员；卸载是双击包里的一个 `.cmd`，它会问你要不要连数据目录一起删。

## 缺点（老实说）

- **它保管着一份能替代你口令的凭据。** 本机管理员——或者拿到硬盘和这台机器 DPAPI 密钥的人——可以解密它。想要「不用输密码就进去」，这一点绕不过去。**所以别用在多人共用的机器上。**
- 需要**管理员装一次**：凭据提供程序必须放进 `System32` 并在注册表注册（登录界面在任何用户配置文件存在之前就要加载它）。
- 只支持 **Windows 10/11 x64**。
- **默认不检查设备类别**：勾上什么，什么连着就算你在场。只勾键盘就是最严的用法；如果你把耳机也勾上，那耳机连着就等于你在场。要恢复「只认 HID 键盘」，命令行里有闸门（`btwu enroll --require-hid Keyboard`）。
- 蓝牙键盘空闲时会自己断连省电，那一刻「在场」会短暂变 0。要是在锁屏界面按回车刚好撞上那一瞬，会不解锁——**再按一次就行**。
- 它不会主动替你锁屏。这是刻意的：BLE 键盘打盹和「人走了」在信号上分不出来，硬要锁就得每个人为自己的键盘调一个宽限期——那种设置页我写过一个版本，最后自己把它删了。

## 怎么开始

1. 双击包里的 `启动管理面板.cmd`（绿色版，整包拷到哪儿都能用；默认那个包不需要装 .NET，另有一个几 MB 的瘦包要求先装 .NET 10 桌面运行时）；
2. 在**最上面的「安装」**里点「安装」——第一次它会先让你勾设备、再录一次 Windows 账户口令（不是 PIN），一次授权（UAC）做完；
3. 以后要改触发设备，就在「触发设备」里勾选后点「保存」；
4. 之后 Win+L 锁屏，键盘在场时按一下回车就回来了。

录口令时它会拿**两种账户名字形式各问 Windows 一次**：如果你填的名字形式不对、而口令是对的，它会直接改用 Windows 接受的那种，而不会把「形式错」说成「口令错」。本机账户到底是**本地账户**还是 **Microsoft 账户**，它也是直接问 Windows（与 `Get-LocalUser` 显示的 `PrincipalSource` 同一个来源），不是靠注册表里有没有微软邮箱猜的——那种猜法在「用过 Store/Office 的本地账户机器」上会把账户名猜错，而错的表现是「锁屏按回车毫无反应、也不报错」。

面板就一页，从上到下：安装 → 触发设备 → 账户口令 → 暂停与启用 → 诊断，最下面是作者信息。托盘右键也是四项，其余都在面板里。
